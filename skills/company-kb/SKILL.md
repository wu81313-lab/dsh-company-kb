# 公司知识库检索流程

适用场景：用户明确说"用知识库查…""查一下公司资料""公司资料里有没有…"，或直接点名知识库内的文件名/目录名。
**用户没有明确要求时不要使用本技能，也不要反复询问是否启用。**

## 检索步骤

1. **先检索，不看目录**：`kb_search` 传一句自然语言需求（例如"农药追溯二维码政策要求"）。
2. **多措并行**：同一需求至少换 2–3 种措辞各查一次，例如
   `二维码政策` / `追溯码编码规则` / `农业农村部公告`。
   命中率靠这一步提升——这是本插件（词法混合检索）的主要补偿手段。
3. **看完整上下文**：对有价值的命中的用 `kb_read`（传 `doc` = 相对路径或 docId）读原文，
   必要时用 `offset` 翻页；PDF/图片是 OCR 文本，遇到明显错字时结合上下文判断。
4. **确认有没有这份资料**：不确定时用 `kb_list`（可按目录、按名称片段过滤）看目录里有什么。
5. **资料不足就明说**：不要编造文号、金额、客户名、标准号。宁可回答"知识库里没有找到 XX"。

## 引用规则

- 引用时给出**相对路径**（`kb_search` 返回的 `rel`），必要时加标题层级与页码。
- 区分来源：标注为 OCR 的内容可能有个别识别错误；标注"仅元数据"的文件没有正文，只能给路径。
- 涉及金额、文号、日期时，建议同时给出处，便于用户复核。

## 索引进度

- 索引是**手动同步**的：用户改了资料后需要点面板「立即同步」或明确说"同步知识库"。
- `kb_status` 可以看：文档数、字数、上次同步时间、失败清单、以及"索引之后有多少文件变了"。
- 如果 `kb_search` 结果里出现"⚠️ 索引之后检测到变化"，应提醒用户同步后重查，而不是断言没有这份资料。
- 索引为空时（从未同步），`kb_status` 会说明；此时应提示用户先同步，而不是给出空结论。

## 会话开关

- 用户点名后本会话一直启用；用户说"关闭知识库"或点了输入框右侧开关则停用。
- 不要为了让检索可用而自行调用 `kb_session on`，也不要自行同步（`kb_status action=now`）。
